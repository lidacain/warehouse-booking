# Warehouse Booking

Бэкенд для записи машин дистрибьюторов на приёмку склада. Тестовое задание.

Организации двух типов — `company` (Астана Моторс, видит и пишет на любой склад) и
`distributor` (видит и пишет только на свои склады). Дистрибьютор записывает партию машин
одним Excel-файлом на конкретный склад и дату, в пределах фиксированного дневного лимита.

## Стек

Python 3.12, FastAPI, SQLAlchemy 2.0 (async), PostgreSQL + asyncpg, Alembic, `pyjwt`,
`openpyxl`, `httpx`, пакетный менеджер `uv`.

## Как запустить локально

Нужны: Python 3.12, [`uv`](https://docs.astral.sh/uv/), Docker (для Postgres).

```bash
# 1. Зависимости
uv sync

# 2. Конфиг — .env.example уже содержит рабочие для локального запуска значения
cp .env.example .env

# 3. Postgres в контейнере
docker compose up -d

# 4. Миграции
cd src && uv run alembic upgrade head && cd ..

# 5. Тестовые данные (организации, склады, несколько активных записей)
uv run python scripts/seed_data.py
```

Дальше нужны **два** постоянно работающих процесса, каждый в своём окне терминала:

```bash
# Основной сервис — http://localhost:8000/docs
uv run uvicorn main:app --reload --app-dir src

# Мок сервиса учёта (другая команда в реальности; здесь — локальная заглушка
# по контракту из задания) — http://localhost:8001/docs
uv run uvicorn mock_accounting:app --port 8001 --reload
```

## Тестовые токены

```bash
uv run python scripts/issue_token.py astana-motors   # company
uv run python scripts/issue_token.py distributor-a   # distributor, владеет складом "Алматы"
uv run python scripts/issue_token.py distributor-b   # distributor, владеет складом "Астана"
```

Вставить в Swagger (`/docs`) → кнопка **Authorize** → `Bearer <токен>`.

## Тестовые данные

`scripts/seed_data.py` создаёт:

- организации: «Астана Моторс» (company), «Дистрибьютор А», «Дистрибьютор Б»;
- склады: «Склад Алматы» (дистрибьютор А, лимит 5/день), «Склад Астана» (дистрибьютор Б, лимит 3/день);
- несколько активных записей на сегодня и завтра — чтобы календарь сразу показывал не только нули.

## Пример Excel-файла

В папке `samples/`:

| Файл | Что проверяет |
|---|---|
| `bookings_sample.xlsx` | Основной пример — одним файлом сразу все причины ответа: успешная запись, нехватка мест, неверный формат VIN, VIN не найден в учёте, дубликат VIN внутри файла, VIN уже имеет активную запись |
| `all_booked.xlsx` | Все строки успешно записываются |

| `empty_data.xlsx` | Файл без единой строки данных (только заголовок) |
| `no_vin_column.xlsx` | Нет колонки с заголовком «VIN» — должен отклонить файл целиком |
| `too_many_rows.xlsx` | 205 строк — больше лимита в 200 |
| `exactly_200_rows.xlsx` | Ровно 200 строк — граничное значение, не должно отклоняться |

## Эндпойнты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/warehouses` | Список складов, видимых организации токена |
| GET | `/warehouses/{id}/calendar?year=&month=` | Занято/лимит по каждому дню месяца |
| GET | `/warehouses/{id}/availability?date=` | Свободно N из M на конкретную дату |
| POST | `/warehouses/{id}/bookings/upload?date=` | Загрузка `.xlsx` с VIN, запись машин |

Все эндпойнты, кроме `/health*`, требуют заголовок `Authorization: Bearer <токен>`.

## Предположения и открытые вопросы

Задание прямо просит уточнять неочевидные места у постановщика — вот что решили
самостоятельно, разумным образом, при отсутствии прямого ответа в задании:

- **Реальный адрес сервиса учёта неизвестен** — используется локальный мок
  (`mock_accounting.py`), повторяющий контракт `POST /api/v1/vehicles/lookup` из задания один в один.
- **Дубликат VIN внутри одного файла** — первая строка обрабатывается обычным порядком,
  повторная отклоняется с причиной «Повторяется в файле (строка N)».
- **Файл больше 200 строк** — отклоняется целиком, до построчной обработки, с реальным
  количеством строк в сообщении (не обрабатываются первые 200).
- **Формат VIN** — проверяется длина (ровно 17 символов, ISO 3779), до обращения к сервису
  учёта; причина отказа называет фактическую длину.
- **Переход записи из `ACTIVE` в `CANCELLED`** — в задании не описан ни один сценарий отмены
  записи (ни ручной, ни автоматической). Модель предусматривает статус `CANCELLED` (нужен для
  осмысленности частичного уникального индекса), но эндпойнта для него нет — без него любой
  записанный VIN физически нельзя будет записать повторно, даже спустя время. Стоило бы уточнить
  у постановщика отдельно.
